02 / ENDPOINT REFERENCE

Эндпоинты

Копируй путь и добавляй его к базовому URL в Postman.

GET/healthПроверить сервер
GET/api/v1/postsСписок, фильтры, пагинация
GET/api/v1/posts/1Получить публикацию
POST/api/v1/postsСоздать JSON-ресурс
PUT/api/v1/posts/1Полностью заменить ресурс
PATCH/api/v1/posts/1Частично изменить ресурс
DELETE/api/v1/posts/1Удалить ресурс (204)
GET/api/v1/usersСписок пользователей
GET/api/v1/users/1Пользователь по ID
GET/api/v1/secure/profileЗаголовок X-API-Key
GET/api/v1/status/418Практика статус-кодов

JSON для POST / PUT

{
  "title": "Моя публикация",
  "body": "Отправлено через Postman",
  "userId": 1
}

Добавь заголовок Content-Type: application/json.

Query-параметры

/api/v1/posts?userId=2&limit=3&offset=0
/api/v1/posts?q=HTTP

Параметры запроса помогают фильтровать и разбивать результаты на страницы.

03 / PRACTICE

Практические задания

01. Первый GET-запрос · Начальный

Получи список публикаций, затем запроси публикацию с ID 3. Сравни статус, заголовки и JSON.

02. Query-параметры · Начальный

Получи публикации пользователя 2, максимум 3 результата, пропусти первые два: ?userId=2&limit=3&offset=2.

03. Создание через POST · Начальный

Отправь JSON с title, body, userId. Ожидаемый статус — 201 Created. Попробуй убрать обязательное поле.

04. PUT против PATCH · Средний

Обнови только title через PATCH. Затем используй PUT с полным объектом и сравни ответы.

05. Ошибки · Средний

Запроси неизвестный ID (404), отправь POST без title (422), проверь невалидные query-параметры.

06. DELETE · Средний

Удали публикацию, затем запроси её снова. DELETE возвращает 204 без тела.

07. API key · Продвинутый

Запроси /api/v1/secure/profile без заголовка X-API-Key (401), затем с X-API-Key: lab-demo-key (200).

08. Python requests · Продвинутый

Используй requests.get, params, timeout, raise_for_status() и обработку RequestException.

04 / DEPLOYMENT

Как опубликовать проект

1. API на Render

Создай Web Service из репозитория. Root Directory: api. Build Command: pip install -r requirements.txt. Start Command:

uvicorn main:app --host 0.0.0.0 --port $PORT

Выбери бесплатный instance и дождись URL. Первый запрос после простоя может быть медленным.

Открыть Render ↗

2. Сайт на GitHub Pages

Создай отдельный репозиторий для сайта и загрузи содержимое папки site в корень. Включи Settings → Pages → Deploy from a branch → main → /(root).

Потом вставь URL Render в поле выше.

GitHub Pages ↗

Данные хранятся в памяти сервера и могут сбрасываться после перезапуска или холодного старта. Демонстрационный ключ публичный — не используй настоящие секреты.

05 / PYTHON

Тот же API через Python

import requests

BASE_URL = "http://127.0.0.1:8000"  # или URL Render
response = requests.get(
    f"{BASE_URL}/api/v1/posts",
    params={"userId": 1, "limit": 5},
    timeout=10,
)
print(response.status_code)
response.raise_for_status()
for post in response.json()["items"]:
    print(post["id"], post["title"])

Установка: python -m pip install requests. Подробности — в api/client.py.
